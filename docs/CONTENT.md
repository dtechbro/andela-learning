# Content quality and provenance

## Source policy

Prefer university materials, recognised open textbooks, and reputable educational institutions. For the provisional biology course, investigate OpenStax Biology 2e as a candidate; verify the actual relevant sections and reuse terms before using content. This document does not assert that any specific question has been verified.

Never fabricate links, quotations, institutional alignment, or review credentials. Write original questions and explanations supported by the source. Credit sources and follow applicable licensing and attribution requirements. Avoid copying large passages.

## Required question fields

Each question needs a stable ID, concept ID, question type, prompt, expected answer or criteria, hint, explanation, source title, source URL, relevant section, and validation status. Multiple-choice items also need stable option IDs and exactly one correct answer unless explicitly designed otherwise.

Track source-check date and verification method. Human review is distinct from agent source checking. Seed content must be labelled sample material; do not claim lecturer approval.

## Writing rules

- Test one clear concept per question.
- Use plain language and define specialist terms where useful.
- Mix recall and application; do not rely entirely on recognition.
- Hints help retrieval without immediately revealing the answer.
- Distractors should reflect plausible misconceptions, not trick wording.
- Short-answer criteria list essential points and acceptable alternatives.
- Explanations address why an answer is correct and the common misunderstanding.
- Avoid stereotypes and unsupported regional or curricular assumptions.
- Provide alternative questions for concepts so review tests understanding rather than memorised wording.

## Validation before inclusion

1. Read the relevant source section.
2. Check that prompt, answer, hint, and explanation agree with it.
3. Check ambiguity, difficulty, licensing, and attribution.
4. Run schema validation and verify question/concept IDs and source fields.
5. Record actual verification status. Exclude unverified questions from ordinary practice.

If source access blocks verification, continue implementation using explicitly isolated demo fixtures; report the content blocker. Do not call the learning prototype validated until representative practice content has been checked.

Local feedback flags exclude the affected question from that device's future practice. They are not a moderation pipeline. Interface translations and translated subject content are separate tasks; scientific terminology requires review.
